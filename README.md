# LLM Studio

หน้าเว็บควบคุมการเทรน/ทดสอบโมเดลภาษาไทยในเครื่อง local — ครอบขั้นตอน
เลือกโมเดลพื้นฐาน → เทรนด้วย LoRA (Unsloth) → แปลงเป็น GGUF → สร้างเข้า
Ollama → ทดสอบแชท ไว้ในหน้าเว็บเดียว แทนการพิมพ์คำสั่งทีละสเต็ปใน
terminal ตามที่ทำใน `thai-local-llm-guide.md`

ทุกอย่างรันบนเครื่องคุณเอง ไม่มีข้อมูลอะไรออกไปที่อื่นนอกจากที่
Unsloth/Ollama เรียก HuggingFace หรือ pull โมเดลตามปกติอยู่แล้ว

## สถาปัตยกรรม

```
frontend/   React + TypeScript + Vite + Tailwind  (หน้าเว็บ, พอร์ต 5173)
backend/    FastAPI (Python)                       (สั่งงานจริง, พอร์ต 8800)
```

Backend เป็นตัวที่ชี้คำสั่งไปรัน:
- สคริปต์เทรน (`train_lora.py` ที่ generate ให้อัตโนมัติตามพารามิเตอร์ที่ตั้งในหน้าเว็บ)
- สคริปต์ export GGUF ผ่าน Unsloth
- `ollama create` / `ollama rm` / Ollama chat API (`localhost:11434`)

Frontend เป็นแค่หน้าตา ไม่รันอะไรหนักเอง — เรียก backend ผ่าน `/api/*`
(proxy ไว้ใน `vite.config.ts` แล้ว ไม่ต้องตั้ง CORS เพิ่ม)

## ข้อกำหนดเบื้องต้น

ต้องมีสภาพแวดล้อมที่ตั้งไว้แล้วตามคู่มือ `thai-local-llm-guide.md`:
- Python venv ที่ลง `unsloth`, `trl`, `peft`, `accelerate`, `bitsandbytes`, `torch` (CUDA build) ไว้แล้ว
- Ollama ติดตั้งและรันอยู่ (`ollama serve` หรือรันผ่าน app ปกติ)
- Node.js 18+ สำหรับฝั่ง frontend

## ตั้งค่า AI ช่วยเตรียม dataset (ไม่บังคับ)

ถ้าอยากใช้ปุ่ม "ให้ AI ช่วยแปลง" ตอนสร้างชุดข้อมูลของตัวเอง ต้องมี Gemini API
key (ฟรี):

1. ขอคีย์ที่ [aistudio.google.com/apikey](https://aistudio.google.com/apikey) (ล็อกอินด้วย Google account)
2. สร้างไฟล์ `backend/.env` ใส่บรรทัดเดียว:
   ```
   GEMINI_API_KEY=ค่าคีย์ที่ได้มา
   ```
3. restart backend (`Ctrl+C` แล้วรัน `uvicorn main:app --reload --port 8800` ใหม่)
4. เช็คสถานะได้ที่หน้า "ตั้งค่า" ในเว็บ — ถ้าขึ้นวงเขียว "พร้อมใช้งาน" แปลว่าเรียบร้อย

ไม่ตั้งก็ใช้งานส่วนอื่นได้ปกติ แค่ปุ่ม AI ช่วยแปลงจะกดไม่ได้ (เพิ่มคู่คำถาม-คำตอบเองด้วยมือได้เสมอ)

> **หมายเหตุ**: Google เปลี่ยนชื่อ/ปลดระวางรุ่นโมเดล Gemini เป็นระยะ (เช่น
> `gemini-2.0-flash` ที่เคยใช้ถูกปลดไปแล้ว ตอนนี้ใช้ `gemini-3.8-flash` แทน)
> โค้ดใน `backend/ai_provider.py` จะลองไล่รุ่นที่รู้จักให้อัตโนมัติถ้าเจอ error
> 404 แบบ "model ... is no longer available" ไม่ต้องแก้โค้ดเอง แต่ถ้าในอนาคต
> Google เปลี่ยนชื่ออีกและรายชื่อในโค้ดตามไม่ทัน ตั้งค่า override เองได้ด้วย
> การเพิ่มบรรทัด `GEMINI_MODEL=ชื่อรุ่นที่ต้องการ` ใน `backend/.env`

## วิธีรัน

เปิด 2 terminal แยกกัน (อย่าปิดระหว่างใช้งาน):

**Terminal 1 — Backend**
```powershell
cd backend
# activate venv ที่มี unsloth ก่อน เช่น
#..\..\AiProject\aiproject-env\Scripts\activate 
pip install -r requirements.txt
uvicorn main:app --reload --port 8800
```

**Terminal 2 — Frontend**
```powershell
cd frontend
npm install
npm run dev
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:5173`

> หมายเหตุ: backend จะสร้างไฟล์โมเดล/สคริปต์ชั่วคราวไว้ที่ `~/AiProject`
> (โฟลเดอร์เดียวกับที่ใช้ตาม `thai-local-llm-guide.md`) แก้ที่
> `backend/jobs.py` ตัวแปร `PROJECT_ROOT` ได้ถ้าอยากเปลี่ยนที่เก็บ

## การใช้งาน

1. **ภาพรวม** — เห็นงานเทรนล่าสุดและจำนวนโมเดลที่มีอยู่
2. **เทรนโมเดลใหม่** — เลือกโมเดลพื้นฐานและ dataset ได้ 3 ทาง:
   - **ค้นหาจาก Hugging Face** — พิมพ์คีย์เวิร์ด เลือกจากผลค้นหาจริง ไม่ต้องจำ repo id
   - **เพิ่มเอง** (เฉพาะโมเดล) — กรอก repo id ตรงๆ ถ้ารู้อยู่แล้ว
   - **เพิ่มของฉัน** (เฉพาะ dataset) — สร้างชุดข้อมูลเอง 2 แบบในหน้าต่างเดียว:
     พิมพ์คู่คำถาม-คำตอบเองทีละแถว หรือวางข้อความดิบ (เช่น โบรชัวร์/ข้อมูลองค์กร)
     แล้วกด "ให้ AI ช่วยแปลง" ให้ Gemini ช่วยแตกเป็นคู่คำถาม-คำตอบให้ ก่อนบันทึกแก้ไขทีละแถวได้ก่อนเสมอ
   
   โมเดล/dataset ที่เพิ่มเองลบออกจากรายการได้ด้วยไอคอนถังขยะ (ไม่กระทบไฟล์จริงบนเครื่อง
   ยกเว้น dataset ที่ "ของฉัน" ซึ่งลบแล้วไฟล์ `.jsonl` จะหายไปด้วย)

   ตั้งพารามิเตอร์ (r, alpha, max_seq_length, epochs) แล้วกดเริ่ม ระบบจะ
   generate สคริปต์เทรนและรันให้ เห็น log สดและกราฟ loss แบบเรียลไทม์ ถ้า
   log เงียบไปนาน (กำลังโหลดโมเดลใหญ่) จะมีข้อความเตือนให้รู้ว่ายังทำงานอยู่
   ไม่ใช่ค้าง ถ้าเลือกโมเดลที่ VRAM เครื่องไม่พอ จะมีคำเตือนพร้อมลิงก์ไปหน้า
   "นำเข้าโมเดล"
3. **หน้ารายละเอียดงาน** — พอเทรนเสร็จ กด "แปลงเป็น GGUF" แล้ว "สร้างเข้า
   Ollama" ได้ในหน้าเดียว มีปุ่มลบไฟล์ทิ้งเมื่อทดสอบเสร็จแล้ว (สำหรับตอนที่
   ดิสก์ใกล้เต็ม) งานที่ถูกสั่ง "หยุดงาน" หรือจบด้วย error จะมีปุ่ม
   "กลับมารันต่อ" ให้กด — ระบบเซฟ checkpoint อัตโนมัติทุก 20 step ระหว่าง
   เทรน กดกลับมารันต่อแล้วจะไปต่อจาก checkpoint ล่าสุด ไม่เริ่มนับใหม่จาก
   ศูนย์ (ใช้ได้ทั้งกรณีกดหยุดเอง และกรณีปิดคอม/ปิด backend กลางคัน)
   ตัวข้อมูลงานบันทึกลงไฟล์ (`studio_data/jobs.json`) แล้ว ปิด/เปิด backend
   ใหม่ก็ยังเห็นงานเก่าและทำทุกอย่างได้ตามปกติ
4. **นำเข้าโมเดล** — สำหรับโมเดลที่เทรนจากที่อื่น (เช่น Colab) สอนขั้นตอน
   ในหน้าเดียว แล้วมีฟอร์มสร้างเข้า Ollama ให้เลย ไม่ต้องเปิด cmd
5. **ทดสอบโมเดล** — จัดการชุดคำถามทดสอบ, รันกับโมเดลที่เลือก, ให้คะแนน
   คำตอบ 1-5 ดาว แล้วดู leaderboard เทียบคะแนนเฉลี่ยระหว่างโมเดลได้
6. **โมเดลของฉัน** — ดูโมเดลทั้งหมดที่อยู่ใน Ollama ทดสอบแชทได้ในหน้าเว็บ
   เลย (ไม่ต้องสลับไปเปิด Open WebUI) และลบโมเดลที่ไม่ใช้แล้ว

## ข้อจำกัดที่รู้อยู่แล้ว (เวอร์ชันนี้)

- การเทรนยังรันเป็น job เดียวที่ละตัว (ไม่มีคิวหลายงานพร้อมกัน)
- ยังไม่เชื่อม Google Colab อัตโนมัติ (ตามที่คุยกันไว้เป็นเฟสถัดไป) — ตอนนี้
  ช่วยแค่ "สอนขั้นตอน + ฟอร์มนำเข้า" (หน้า "นำเข้าโมเดล") ยังไม่ได้สั่งรันบน
  Colab จากเว็บนี้โดยตรง
- ไม่มีระบบ login/multi-user เพราะออกแบบไว้ใช้คนเดียวบนเครื่อง local
- สถานะ job เก็บในหน่วยความจำ (ไม่ persist) — ถ้า restart backend
  ประวัติ job เก่าจะหายไป (ตัวไฟล์โมเดลที่เทรนเสร็จแล้วไม่หาย) ส่วนแคตตาล็อก
  โมเดลและผลทดสอบ (eval) เก็บเป็นไฟล์ JSON ใน `studio_data/` ไม่หายเมื่อ
  restart

## แก้ปัญหาที่พบบ่อย

**กด "หยุดงาน" แล้วกลับมาหน้ารายละเอียดงาน ปุ่มหายหมด/ลบไฟล์ไม่ได้ เหมือนเว็บ crash**
(แก้แล้วตั้งแต่ v0.4.0) ต้นเหตุคือข้อมูลงานเก็บไว้ในหน่วยความจำ backend อย่างเดียว
พอ backend ถูกปิดหรือรีสตาร์ท (ไม่ว่าจะตั้งใจเพราะคิดว่าเว็บค้าง หรือ crash เอง)
ข้อมูลงานทั้งหมดหายไปทันทีแม้ไฟล์โมเดลจริงจะยังอยู่ครบ — ตอนนี้บันทึกงานลงไฟล์
อัตโนมัติแล้ว ถ้ายังเจออาการนี้อยู่หลังอัปเดต แปลว่า backend ที่รันอยู่เป็นเวอร์ชัน
เก่ากว่า v0.4.0 ให้ลองโหลดโค้ดชุดใหม่แล้ว restart ดูอีกครั้ง

**`[SSL: CERTIFICATE_VERIFY_FAILED] self-signed certificate in certificate chain`**
ตอนดาวน์โหลดโมเดลจาก Hugging Face (เช่นระหว่างเทรน Qwen2.5-7B) — นี่ไม่ใช่บั๊กของ
LLM Studio แต่เป็นเพราะมี "self-signed certificate" โผล่เข้ามาแทรกใน chain ระหว่าง
เครื่องกับ huggingface.co ซึ่งปกติเกิดจากไฟร์วอลล์/อุปกรณ์เครือข่ายที่ทำ **SSL deep
inspection** (แกะ HTTPS ดูเนื้อหาข้างในแล้วเซ็นใบรับรองใหม่ด้วย CA ของตัวเอง) — ถ้า
เครื่องเทรนอยู่หลัง FortiGate ที่เพิ่งย้ายมาใหม่ นี่คือสาเหตุที่เป็นไปได้สูงสุด เพราะ
ค่าเริ่มต้นของ Deep Inspection profile จะไปสกัดทราฟฟิก HTTPS ไปยัง huggingface.co
ด้วย แต่ไลบรารี Python (`requests`/`httpx`/`huggingface_hub`) ไม่รู้จัก/ไม่เชื่อถือ CA
ของไฟร์วอลล์ เลย verify ไม่ผ่าน แก้ได้ 2 ทาง (เลือกทางใดทางหนึ่งพอ):

1. **แก้ที่ไฟร์วอลล์ (แนะนำ ทำครั้งเดียวจบทั้งองค์กร)** — ใน FortiGate ไปที่ SSL/SSH
   Inspection profile ที่ใช้งานอยู่ แล้วเพิ่ม exemption (SSL Exempt) ให้โดเมน
   `huggingface.co`, `*.huggingface.co`, และ `cdn-lfs.huggingface.co` ไม่ต้องถูก
   deep-inspect (เหมือน exemption ที่มักทำให้ banking/Windows Update อยู่แล้ว)
2. **แก้ที่เครื่องเทรน** — export root CA certificate ที่ FortiGate ใช้เซ็น (ปกติชื่อ
   ประมาณ `Fortinet_CA_SSL` หรือชื่อที่ตั้งเอง) ออกมาเป็น `.pem/.cer` แล้ว:
   - ติดตั้งเข้า Windows Certificate Store (Trusted Root Certification Authorities) ให้เครื่องเชื่อถือถาวร หรือ
   - เพิ่มเข้าไฟล์ certificate bundle ของ Python (`pip show certifi` หาตำแหน่ง `cacert.pem` แล้ว append CA ต่อท้ายไฟล์นั้น) หรือตั้ง environment variable `REQUESTS_CA_BUNDLE=` ชี้ไปไฟล์ bundle ที่รวม CA นี้ไว้แล้ว

   ไม่แนะนำให้ปิดการ verify SSL ทิ้งไปเลย (เช่น `REQUESTS_CA_BUNDLE=` ว่าง หรือ
   `verify=False`) เพราะจะเสี่ยงเรื่องความปลอดภัยของทราฟฟิกทั้งหมด ไม่ใช่แค่ส่วนนี้

**`Gemini API ตอบกลับ error: 404 ... model ... is no longer available`**
Google ปลดระวาง/เปลี่ยนชื่อรุ่น Gemini เป็นระยะ ตั้งแต่เวอร์ชันนี้ `ai_provider.py`
จะไล่ลองรุ่นที่รู้จักให้เองอัตโนมัติเมื่อเจอ 404 แบบนี้ ถ้ายังเจอ error เดิมอยู่
(แปลว่า Google เปลี่ยนชื่ออีกและโค้ดตามไม่ทัน) ให้ดูชื่อรุ่นใหม่จากข้อความ error
เอง แล้วเพิ่มบรรทัด `GEMINI_MODEL=ชื่อรุ่นใหม่` ในไฟล์ `backend/.env` แล้ว restart
backend
