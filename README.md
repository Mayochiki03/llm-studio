# LLM Studio

หน้าเว็บควบคุมการเทรน/ทดสอบโมเดลภาษาไทยในเครื่อง local — ครอบขั้นตอน
เลือกโมเดลพื้นฐาน → เทรนด้วย LoRA (Unsloth) → แปลงเป็น GGUF → สร้างเข้า
Ollama → ทดสอบแชท ไว้ในหน้าเว็บเดียว แทนการพิมพ์คำสั่งทีละสเต็ปใน
terminal ตามที่ทำใน `thai-local-llm-guide.md`

ทุกอย่างรันบนเครื่องคุณเอง ไม่มีข้อมูลอะไรออกไปที่อื่นนอกจากที่
Unsloth/Ollama เรียก HuggingFace หรือ pull โมเดลตามปกติอยู่แล้ว

นอกจากเทรน ตั้งแต่ v0.5.0 ยังมี **คลังความรู้ + Playground** (ให้โมเดลตอบจากเอกสารของเราโดยไม่ต้องเทรนใหม่),
**ตรวจก่อนเทรนและคิวงาน**, **ชุดข้อมูลมีเวอร์ชันและตรวจข้อมูลระบุตัวตน**, **ทะเบียนโมเดล** (อนุมัติก่อนใช้งานจริง ย้อนกลับได้),
**เปรียบเทียบโมเดล**, และ **ระบบ/ความปลอดภัย** (ล็อกอิน, สำรอง/กู้คืน, ล้างพื้นที่, audit log)

## สถาปัตยกรรม

```
frontend/   React + TypeScript + Vite + Tailwind  (หน้าเว็บ, พอร์ต 5173 ตอนพัฒนา)
backend/    FastAPI (Python)                       (สั่งงานจริง, พอร์ต 8800)
```

ตอนพัฒนารัน 2 พอร์ต (หน้าเว็บ proxy `/api` ไปหา backend) ตอนใช้งานจริงบนเซิร์ฟเวอร์ให้บิลด์หน้าเว็บ (`npm run build`)
แล้ว backend จะเสิร์ฟให้เองที่พอร์ตเดียว (ดู "โหมดเซิร์ฟเวอร์")

ข้อมูลของระบบเก็บใน `<โฟลเดอร์โปรเจกต์>/studio_data/` (`studio.db` = คลังความรู้/ทะเบียนโมเดล/audit,
`settings.json` = ตั้งค่า, `jobs.json` = งานเทรน, ชุดข้อมูลของเรา) โฟลเดอร์โปรเจกต์หาจากตัวแปร `LLM_STUDIO_ROOT` →
`E:/AiProject` (Windows ถ้ามี) → `~/AiProject`

Backend เป็นตัวที่ชี้คำสั่งไปรัน:
- สคริปต์เทรน (`train_lora.py` ที่ generate ให้อัตโนมัติตามพารามิเตอร์ที่ตั้งในหน้าเว็บ)
- สคริปต์ export GGUF ผ่าน Unsloth
- `ollama create` / `ollama rm` / Ollama chat API (`localhost:11434`)

Frontend เป็นแค่หน้าตา ไม่รันอะไรหนักเอง — เรียก backend ผ่าน `/api/*`
(proxy ไว้ใน `vite.config.ts` แล้ว ไม่ต้องตั้ง CORS เพิ่ม)

## ข้อกำหนดเบื้องต้น

ต้องมีสภาพแวดล้อมที่ตั้งไว้แล้วตามคู่มือ `thai-local-llm-guide.md`:
- Python venv ที่ลง `unsloth`, `trl`, `peft`, `accelerate`, `bitsandbytes`, `torch` (CUDA build) ไว้แล้ว
- Ollama ติดตั้งและรันอยู่ (`ollama serve` หรือรันผ่าน app ปกติ)
- Node.js 18+ สำหรับฝั่ง frontend
- สำหรับคลังความรู้แบบค้นตามความหมาย: `ollama pull bge-m3` (โมเดลสร้างเวกเตอร์ รองรับภาษาไทย) ถ้าไม่ดึง ระบบค้นด้วยคำแทนและเตือนในหน้าคลังความรู้

### ตั้งค่าการ์ดจอบน Windows (สิ่งที่ต้องทำก่อนเทรนครั้งแรก)

ผ่านการทดสอบจริงบน RTX 3050 4GB / Windows 11 / Python 3.11 — ปัญหาไดรเวอร์ที่เจอบ่อยอยู่ตรงนี้ทั้งหมด:

1. **torch ต้องเป็นรุ่น CUDA** (ถ้าเป็น `+cpu` Unsloth จะขึ้นว่าไม่เจอ GPU):
   ```
   pip uninstall -y torch torchvision torchaudio
   pip install torch==2.12.1 torchvision torchaudio --index-url https://download.pytorch.org/whl/cu126
   python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.version.cuda)"
   ```
   ต้องได้ `...+cu126 True 12.6`
2. **Triton บน Windows**: `pip install triton-windows` (ตรวจด้วย `pip list | findstr triton`)
3. **ตัวคอมไพล์ C**: ติดตั้ง *Visual Studio Build Tools* (เลือก "Desktop development with C++")
   แล้วเปิด **Developer PowerShell for VS** รัน backend จากหน้าต่างนั้น ไม่งั้นจะขึ้น `Failed to find C compiler`
4. **เคลียร์ VRAM ก่อนเทรน**: `ollama ps` ถ้ามีโมเดลค้างให้ `ollama stop <ชื่อ>`, ปิดเบราว์เซอร์/โปรแกรมที่ใช้การ์ดจอ, เช็คด้วย `nvidia-smi`
   (การ์ด 4GB ถ้า VRAM ไม่พอจะล้มด้วย `No or negligible GPU memory available for fused cross entropy`)
5. ดาวน์โหลดโมเดลจาก Hugging Face ต้องมีเน็ตตลอด ถ้าขึ้น `getaddrinfo failed` ให้สั่งเทรนซ้ำ (ไฟล์ที่โหลดแล้วต่อจากเดิม)

## ตั้งค่า AI ช่วยเตรียม dataset (ไม่บังคับ)

ถ้าอยากใช้ปุ่ม "ให้ AI ช่วยแปลง" ตอนสร้างชุดข้อมูลของตัวเอง ต้องมี Gemini API
key (ฟรี):

1. ขอคีย์ที่ [aistudio.google.com/apikey](https://aistudio.google.com/apikey) (ล็อกอินด้วย Google account)
2. สร้างไฟล์ `backend/.env` ใส่บรรทัดเดียว:
   ```
   GEMINI_API_KEY=ค่าคีย์ที่ได้มา
   ```
3. restart backend (`Ctrl+C` แล้วรัน `python -m uvicorn main:app --reload --port 8800` ใหม่)
4. เช็คสถานะได้ที่หน้า "ตั้งค่า" ในเว็บ — ถ้าขึ้นวงเขียว "พร้อมใช้งาน" แปลว่าเรียบร้อย

ไม่ตั้งก็ใช้งานส่วนอื่นได้ปกติ แค่ปุ่ม AI ช่วยแปลงจะกดไม่ได้ (เพิ่มคู่คำถาม-คำตอบเองด้วยมือได้เสมอ)

> **หมายเหตุ**: Google เปลี่ยนชื่อ/ปลดระวางรุ่นโมเดล Gemini เป็นระยะ (เช่น
> `gemini-2.0-flash` ที่เคยใช้ถูกปลดไปแล้ว ตอนนี้ใช้ `gemini-3.8-flash` แทน)
> โค้ดใน `backend/ai_provider.py` จะลองไล่รุ่นที่รู้จักให้อัตโนมัติถ้าเจอ error
> 404 แบบ "model ... is no longer available" ไม่ต้องแก้โค้ดเอง แต่ถ้าในอนาคต
> Google เปลี่ยนชื่ออีกและรายชื่อในโค้ดตามไม่ทัน ตั้งค่า override เองได้ด้วย
> การเพิ่มบรรทัด `GEMINI_MODEL=ชื่อรุ่นที่ต้องการ` ใน `backend/.env`

## วิธีรัน

### โหมดพัฒนา (2 terminal)

**Terminal 1 — Backend**
```powershell
cd backend
# activate venv ที่มี unsloth ก่อน
pip install -r requirements.txt
python -m uvicorn main:app --reload --port 8800
```
> ใช้ `python -m uvicorn` ไม่ใช่ `uvicorn` เฉยๆ เพราะบางเครื่อง Windows หาคำสั่ง `uvicorn` ไม่เจอ (ไม่อยู่ใน PATH)

**Terminal 2 — Frontend**
```powershell
cd frontend
npm install
npm run dev
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:5173`

> ต้องมีไฟล์ `frontend/package.json` ครบก่อนรัน `npm install` (ถ้าขึ้น ENOENT package.json แปลว่าโฟลเดอร์ `frontend` ไม่ครบ ให้แตกซิปใหม่)

### โหมดเซิร์ฟเวอร์ (พอร์ตเดียว เหมาะกับ Ubuntu + RTX 4090)

```bash
./start.sh                 # ครั้งแรกจะบิลด์หน้าเว็บให้ แล้วเปิดที่ http://127.0.0.1:8800
HOST=0.0.0.0 ./start.sh    # ให้เครื่องอื่นในวง LAN เข้าได้
```
Windows: `start.bat` (activate venv ก่อน)

**ก่อนเปิดให้เครื่องอื่นเข้า ให้ตั้งรหัสผ่านที่หน้า "ตั้งค่า" → "ความปลอดภัย" ก่อนเสมอ** และควรให้อยู่หลังไฟร์วอลล์/VPN ภายในโรงพยาบาล
(ระบบไม่มี HTTPS ในตัว ถ้าต้องเข้ารหัสให้ใส่ reverse proxy เช่น Caddy/nginx ข้างหน้า) ข้อมูลผู้ป่วยจริงไม่ควรอยู่ในคลังความรู้หรือชุดข้อมูลเทรน

### รันเทสต์อัตโนมัติ (`npm test`)

ติดตั้งครั้งเดียว แล้วสั่งที่โฟลเดอร์นอกสุดของโปรเจกต์:
```bash
cd frontend && npm install && cd ..          # ติดตั้งตัวรันเทสต์หน้าเว็บ (vitest)
pip install -r backend/requirements-dev.txt   # ติดตั้ง pytest (ใน venv เดียวกับที่รัน backend)
npm test                                      # รันทั้งสองชุด: หน้าเว็บ 110 ข้อ + backend 135 ข้อ (เดโมแยก: node --test demo/test.mjs)
```
- `npm run test:web` = เฉพาะหน้าเว็บ (เร็ว ไม่ต้องมี Python) · `npm run test:api` = เฉพาะ backend
- ฝั่ง Python ไม่มี `npm test` ในตัว เขาใช้ **pytest** (`python -m pytest tests -q` ที่โฟลเดอร์ `backend`) ซึ่งเทียบได้กับ jest/vitest — `npm test` ที่โฟลเดอร์นอกสุดแค่เรียกให้ทั้งสองตัว
- ทั้งสองชุดใช้ Ollama/backend จำลอง ไม่ต้องมี GPU ไม่แตะข้อมูลจริง (backend ใช้โฟลเดอร์ชั่วคราว)
- ชุดหน้าเว็บเปิดทุกหน้าใน 4 สถานการณ์ (ข้อมูลปกติ, เครือข่ายล่ม, ตอบ 500, ข้อมูลรูปแบบแปลก) แล้วเช็คว่าไม่ขึ้น "หน้านี้แสดงผลไม่ได้" — เหมาะรันหลังแก้โค้ดทุกครั้ง
- **ไม่ได้ทดสอบการเทรนจริง** (ต้องมี GPU) ต้องลองบนเครื่องจริง

### ถ้าหน้าจอว่าง / ระบบทำงานแปลก
1. เปิดหน้า **เครื่องและพื้นที่ → บันทึกการทำงาน** สลับดู "ฝั่งหน้าเว็บ" (error ของเบราว์เซอร์) และ "ฝั่งเซิร์ฟเวอร์"
2. กด **คัดลอกข้อมูลวินิจฉัย** แล้ววางส่งให้ผู้พัฒนา (ไม่มีรหัสผ่าน/คีย์/เนื้อหาแชท)
3. ถ้าเปิดหน้าไม่ได้เลย: ไฟล์ log อยู่ที่ `studio_data/logs/backend.log` และ `client.log` (ในโฟลเดอร์โปรเจกต์ ดูตำแหน่งที่หน้า ตั้งค่า → ตำแหน่งโปรเจกต์) หรือกด F12 → แท็บ Console ดูข้อความสีแดง
4. error 500 จะมี "รหัสอ้างอิง" 8 ตัวอักษร ค้นรหัสนั้นใน `backend.log` เพื่อดู traceback

### เรียกใช้จากระบบอื่น (API)
สร้างคีย์ที่ **ตั้งค่า → คีย์ API สำหรับระบบอื่น** (คีย์เต็มแสดงครั้งเดียว) แล้วเรียก:
```bash
curl -X POST http://<เซิร์ฟเวอร์>:8800/api/v1/ask \
  -H "Authorization: Bearer sk-llmstudio-..." -H "Content-Type: application/json" \
  -d '{"question":"ผู้ป่วยหยุดยาเองต้องทำอย่างไร","use_kb":true}'
```
`GET /api/v1/health` · `GET /api/v1/model` (โมเดลที่ใช้งานจริง) · `POST /api/v1/search` (ค้นคลังความรู้อย่างเดียว) — ตอบจากโมเดลที่ตั้งเป็น "ใช้งานจริง" ในทะเบียน จำกัด 60 ครั้ง/นาที/คีย์ ถ้าไม่มีโมเดลใช้งานจริงจะตอบ 503

## การใช้งาน

เมนูซ้ายเรียงตามลำดับงานจริง (บนมือถือกดปุ่มเมนูมุมซ้ายบน)

1. **ภาพรวม** — โมเดลที่ใช้งานจริง คิวเทรน คลังความรู้ GPU/ดิสก์ และงานเทรนล่าสุด
2. **คลังความรู้** — เพิ่มข้อความ คู่ถาม-ตอบ หรืออัปโหลดไฟล์ (txt, md, csv, pdf, docx) ระบบตัดเป็นชิ้นและสร้างเวกเตอร์ให้
   เปิด/ปิดแต่ละเอกสาร ดูประวัติและย้อนเวอร์ชัน นำเข้า/ส่งออก JSONL และ "ทดสอบการค้นหา" ดูว่าระบบดึงชิ้นไหนมา
   (ความรู้ใหม่ใช้ได้ทันทีโดยไม่ต้องเทรน)
3. **ชุดข้อมูลเทรน** — ชุดข้อมูลของเรา มีเวอร์ชัน ดูตัวอย่าง เพิ่มตัวอย่าง สแกนข้อมูลระบุตัวตน (เลขบัตร/HN/เบอร์โทร/อีเมล) และ
   สร้างจากคู่ถาม-ตอบในคลังความรู้ ถ้าพบข้อมูลระบุตัวตนร้ายแรง ระบบจะไม่ยอมเริ่มเทรนจนกว่าจะแก้หรือกดยืนยัน
4. **เทรนโมเดลใหม่** — 4 ขั้นตอน: โมเดลพื้นฐาน → ชุดข้อมูล → ตั้งค่า → ตรวจและเริ่ม
   - เลือกโมเดล/ชุดข้อมูลได้ 3 ทางเหมือนเดิม: **ค้นหาจาก Hugging Face**, **เพิ่มเอง**, **เพิ่มของฉัน** (พิมพ์เอง หรือวางข้อความแล้วให้ Gemini ช่วยแตกเป็นคู่ถาม-ตอบ)
   - **แบบง่าย**: เลือก "ทดลองเร็ว / สมดุล / คุณภาพสูง" ระบบเลือก batch และตัวเร่งความเร็วให้ตามการ์ดจอ
     **ขั้นสูง**: ปรับ r, alpha, ความยาวข้อความ, epochs, learning rate, batch, accumulation, packing, สัดส่วน validation,
     รูปแบบ prompt, system prompt, เวลาสูงสุด
   - **ตั้งเวลาเริ่ม** ได้ (เช่น สั่งตอนเย็นให้เริ่มตอนกลางคืน) ไม่ตั้ง = เข้าคิวและเริ่มเมื่อการ์ดจอว่าง
   - ขั้นสุดท้ายมี **Preflight** (VRAM/RAM/ดิสก์ เป็นไฟเขียว/เหลือง/แดง) ถ้าแดงต้องกด "ฝืนเริ่ม" เอง
5. **หน้ารายละเอียดงาน** — log สด กราฟ loss (เทียบกับ validation loss ถ้าเปิด) ลำดับคิว/ดันขึ้นคิวแรก
   พอเสร็จกด "แปลงเป็น GGUF" แล้ว "สร้างเข้า Ollama" โมเดลจะถูกลงทะเบียนเป็น "รอตรวจ" ในทะเบียนโมเดลให้เอง
   งานที่หยุด/ล้มกด "กลับมารันต่อ" ได้ (เซฟ checkpoint อัตโนมัติ) งานและคิวบันทึกลงไฟล์ รีสตาร์ท backend แล้วไม่หาย
   (งานที่กำลังรันตอนปิดเครื่องจะกลายเป็น "หยุดแล้ว" ให้กดรันต่อ)
6. **นำเข้าโมเดล** — สำหรับโมเดลที่เทรนจากที่อื่น (เช่น Colab) สอนขั้นตอนและมีฟอร์มสร้างเข้า Ollama
7. **ทดสอบและเปรียบเทียบ** — ชุดคำถามทดสอบ แต่ละข้อใส่เกณฑ์ตรวจอัตโนมัติได้ (ต้องมีคำ/ห้ามมีคำ) ตรึงโจทย์ และกำหนดเป็นเคส
   red flag (เช่น ผู้ป่วยมีความเสี่ยงฉุกเฉิน) รันกับโมเดลแล้วให้ดาว หรือเลือกหลายโมเดลมาเทียบเคียงข้างกัน
8. **Playground** — คุยกับโมเดลแบบสตรีม เปิด/ปิดใช้คลังความรู้ ดูว่าคำตอบใช้ความรู้ชิ้นไหน (พร้อมคะแนน)
9. **ทะเบียนโมเดล** — โมเดลทุกตัวผ่าน รอตรวจ → รันทดสอบ → อนุมัติ → ใช้งานจริง (ใช้งานจริงได้ทีละตัว) ย้อนกลับเวอร์ชันก่อนหน้าได้
   เว็บระบบอื่นเรียก `GET /api/registry/active` เพื่อรู้ว่าตอนนี้ควรถามโมเดลชื่ออะไร
10. **โมเดลใน Ollama** — ดูโมเดลทั้งหมด ทดสอบแชท และลบ
11. **เครื่องและพื้นที่** — GPU/RAM/ดิสก์สด, ล้างไฟล์ที่ไม่ใช้ (checkpoint, GGUF เก่า), สำรอง/กู้คืนข้อมูลระบบ,
    คำแนะนำตั้งค่า Ollama ตามการ์ดจอ, audit log
12. **ตั้งค่า** — ที่อยู่ Ollama, โมเดลสร้างเวกเตอร์, ปลด/โหลดโมเดลรอบเทรน, โหมดดาวน์โหลด, เวลาเทรนสูงสุด, system prompt เริ่มต้น,
    พารามิเตอร์คลังความรู้, ตั้ง/เปลี่ยน/ปิดรหัสผ่าน ลืมรหัสผ่าน: ลบส่วน `auth` ใน `studio_data/settings.json` แล้วรีสตาร์ท backend

## เตรียมข้อมูลและชุดตัวอย่าง

- **ชุดข้อมูลเทรน → "สร้างจากตารางข้อเท็จจริง"**: กรอกเรื่องละแถว (คำตอบ + คำถามหลายแบบ + คำสำคัญ) ระบบสร้างชุดข้อมูลเทรนและโจทย์ทดสอบให้ใช้คำชุดเดียวกัน ไม่ต้องใช้ AI
- `samples/pack-02/` ข้อมูลสมมติราว 370 ตัวอย่าง (คำถามคนละสำนวน คำตอบ 3 สำนวนต่อเรื่อง) + ข้อสอบ 50 ข้อ (ข้อเท็จจริง ทักทาย/ตัวตน "นอกขอบเขต → ตอบไม่มีข้อมูล" และ "เอกสารขัดความจำ") โหลดด้วย `cd backend && python load_sample_pack.py --reset --pack 2` (ใส่ `--kb` เพื่อเพิ่มเข้าคลังความรู้ด้วย) อ่านวิธีเทรนใน `samples/pack-02/README.md`
  - ขอบเขตของโมเดล: ในหน้า "ชุดข้อมูลเทรน → สร้างจากตารางข้อเท็จจริง" มีส่วน "ขอบเขต" ให้ใส่เรื่องที่ระบบไม่ควรรู้ (จำนวนชั้น ที่จอดรถ เบอร์ส่วนตัว ฯลฯ) โมเดลจะถูกสอนให้ตอบ "ไม่มีข้อมูล" แทนการเดา และกันบางข้อไว้เป็นข้อสอบ
  - ชุดตรวจ (validation) ของชุดข้อมูลนี้แบ่งตามกลุ่มคำถาม ไม่ให้สำนวนที่เกือบเหมือนกันข้ามฝั่ง จึงเชื่อ val_loss ได้มากขึ้น แต่ความเก่งจริงยังต้องดูผลทดสอบ

## แก้ปัญหาที่พบบ่อย

**กด "หยุดงาน" แล้วกลับมาหน้ารายละเอียดงาน ปุ่มหายหมด/ลบไฟล์ไม่ได้ เหมือนเว็บ crash**
(แก้แล้วตั้งแต่ v0.4.0) ต้นเหตุคือข้อมูลงานเก็บไว้ในหน่วยความจำ backend อย่างเดียว
พอ backend ถูกปิดหรือรีสตาร์ท (ไม่ว่าจะตั้งใจเพราะคิดว่าเว็บค้าง หรือ crash เอง)
ข้อมูลงานทั้งหมดหายไปทันทีแม้ไฟล์โมเดลจริงจะยังอยู่ครบ — ตอนนี้บันทึกงานลงไฟล์
อัตโนมัติแล้ว ถ้ายังเจออาการนี้อยู่หลังอัปเดต แปลว่า backend ที่รันอยู่เป็นเวอร์ชัน
เก่ากว่า v0.4.0 ให้ลองโหลดโค้ดชุดใหม่แล้ว restart ดูอีกครั้ง

**`[SSL: CERTIFICATE_VERIFY_FAILED] self-signed certificate in certificate chain`**
ตอนดาวน์โหลดโมเดลจาก Hugging Face (เช่นระหว่างเทรน Qwen2.5-7B) — นี่ไม่ใช่บั๊กของ
LLM Studio แต่เป็นเพราะมี "self-signed certificate" โผล่เข้ามาแทรกใน chain ระหว่าง
เครื่องกับ huggingface.co ซึ่งปกติเกิดจากไฟร์วอลล์/อุปกรณ์เครือข่ายที่ทำ **SSL deep
inspection** (แกะ HTTPS ดูเนื้อหาข้างในแล้วเซ็นใบรับรองใหม่ด้วย CA ของตัวเอง) — ถ้า
เครื่องเทรนอยู่หลัง FortiGate ที่เพิ่งย้ายมาใหม่ นี่คือสาเหตุที่เป็นไปได้สูงสุด เพราะ
ค่าเริ่มต้นของ Deep Inspection profile จะไปสกัดทราฟฟิก HTTPS ไปยัง huggingface.co
ด้วย แต่ไลบรารี Python (`requests`/`httpx`/`huggingface_hub`) ไม่รู้จัก/ไม่เชื่อถือ CA
ของไฟร์วอลล์ เลย verify ไม่ผ่าน แก้ได้ 2 ทาง (เลือกทางใดทางหนึ่งพอ):

1. **แก้ที่ไฟร์วอลล์ (แนะนำ ทำครั้งเดียวจบทั้งองค์กร)** — ใน FortiGate ไปที่ SSL/SSH
   Inspection profile ที่ใช้งานอยู่ แล้วเพิ่ม exemption (SSL Exempt) ให้โดเมน
   `huggingface.co`, `*.huggingface.co`, และ `cdn-lfs.huggingface.co` ไม่ต้องถูก
   deep-inspect (เหมือน exemption ที่มักทำให้ banking/Windows Update อยู่แล้ว)
2. **แก้ที่เครื่องเทรน** — export root CA certificate ที่ FortiGate ใช้เซ็น (ปกติชื่อ
   ประมาณ `Fortinet_CA_SSL` หรือชื่อที่ตั้งเอง) ออกมาเป็น `.pem/.cer` แล้ว:
   - ติดตั้งเข้า Windows Certificate Store (Trusted Root Certification Authorities) ให้เครื่องเชื่อถือถาวร หรือ
   - เพิ่มเข้าไฟล์ certificate bundle ของ Python (`pip show certifi` หาตำแหน่ง `cacert.pem` แล้ว append CA ต่อท้ายไฟล์นั้น) หรือตั้ง environment variable `REQUESTS_CA_BUNDLE=` ชี้ไปไฟล์ bundle ที่รวม CA นี้ไว้แล้ว

   ไม่แนะนำให้ปิดการ verify SSL ทิ้งไปเลย (เช่น `REQUESTS_CA_BUNDLE=` ว่าง หรือ
   `verify=False`) เพราะจะเสี่ยงเรื่องความปลอดภัยของทราฟฟิกทั้งหมด ไม่ใช่แค่ส่วนนี้

**`Gemini API ตอบกลับ error: 404 ... model ... is no longer available`**
Google ปลดระวาง/เปลี่ยนชื่อรุ่น Gemini เป็นระยะ ตั้งแต่เวอร์ชันนี้ `ai_provider.py`
จะไล่ลองรุ่นที่รู้จักให้เองอัตโนมัติเมื่อเจอ 404 แบบนี้ ถ้ายังเจอ error เดิมอยู่
(แปลว่า Google เปลี่ยนชื่ออีกและโค้ดตามไม่ทัน) ให้ดูชื่อรุ่นใหม่จากข้อความ error
เอง แล้วเพิ่มบรรทัด `GEMINI_MODEL=ชื่อรุ่นใหม่` ในไฟล์ `backend/.env` แล้ว restart
backend

ดูการเปลี่ยนแปลงแต่ละเวอร์ชันได้ใน [`CHANGELOG.md`](./CHANGELOG.md)

## คู่มือ: เตรียมชุดข้อมูลให้ไม่ซ้ำ (0.8.0-0.8.1)

โมเดลที่เทรนจากข้อมูลซ้ำๆ จะ "ท่องประโยค" (train loss ลงต่ำ แต่ val_loss ขึ้น และตอบเพี้ยนกับคำถามสำนวนใหม่) เป้าหมายคือข้อมูลน้อยแต่หลากหลาย ไม่ใช่เยอะแต่ซ้ำ

1. **สร้างจากตารางข้อเท็จจริง** (ชุดข้อมูลเทรน → สร้างจากตารางข้อเท็จจริง) ต่อ 1 เรื่องใส่ คำตอบหลัก + คำถามหลายสำนวน (แนะนำ 8-15 แบบ) + คำตอบสำนวนอื่น 2-3 แบบ (ช่อง "คำตอบสำนวนอื่น" ใจความ ตัวเลข เบอร์โทร ต้องเหมือนคำตอบหลัก ระบบตัดทิ้งเองถ้าไม่มีคำสำคัญ)
2. **ให้ Gemini ช่วยคิด** ปุ่ม "ช่วยคิดคำถามเพิ่ม" / "ช่วยเขียนคำตอบอีกสำนวน" ในแต่ละเรื่อง ต้องมี `GEMINI_API_KEY` ระบบถามยืนยันก่อนส่ง ไม่ส่งถ้าข้อความมีข้อมูลระบุตัวตน ผลลัพธ์เป็นข้อเสนอ ต้องอ่านและแก้เองก่อนสร้างชุดข้อมูล (ตั้งรุ่นแรกด้วย `GEMINI_MODEL=gemini-3.5-flash-lite` ใน `backend/.env` ถ้ารุ่นไหน timeout ระบบข้ามไปรุ่นถัดไปเอง)
3. **ดูรายงานคุณภาพ** ตอนกด "ดูตัวอย่าง" และในหน้าตารางแก้ไข: คำถาม/คำตอบไม่ซ้ำกี่แบบ, คำตอบที่ซ้ำสุดกินกี่ %, คู่คำถามที่คล้ายกัน (ข้ามคู่ที่เป็นคำถามเดียวกันที่ระบบเติมคำนำหน้าเอง) พร้อมคำเตือนเมื่อซ้ำเกิน
4. **แก้เป็นตาราง** ชุดข้อมูลเทรน → ดูชุดที่สร้างเอง → "แก้ไขเป็นตาราง" ค้นหา แก้ในช่อง เพิ่ม/ลบ/ทำซ้ำแถว ติ๊ก "เฉพาะแถวมีปัญหา" เพื่อดูคำถามซ้ำ/คำตอบซ้ำเกิน 8 แถว/แถวไม่ครบ แล้วบันทึกเป็นเวอร์ชันใหม่ (ย้อนกลับได้จากประวัติเวอร์ชัน)
5. **ขอบเขต** รายการคำถามนอกขอบเขตมีคำตอบ "ไม่มีข้อมูล" 4 สำนวนหมุนเวียน (ตั้งคำตอบเองได้ จะใช้สำนวนเดียว) ควรกินไม่เกินราว 10-20% ของข้อมูล
6. **ข้อมูลที่ต้องแม่น** (เบอร์โทร เวลา) ให้คลังความรู้ (RAG) เป็นตัวตอบ การเทรนใช้สอบน้ำเสียงและขอบเขตเป็นหลัก
7. **ตั้งชื่อโมเดลผลลัพธ์** ใหม่ทุกรอบ (เช่น `faq-v4`) ระบบไม่ให้ซ้ำกับงานที่ยังใช้อยู่ และใช้ได้เฉพาะ a-z, 0-9, จุด, ขีดกลาง, ขีดล่าง
8. ตอนเทรนเสร็จ ระบบใช้จุดที่ val_loss ต่ำสุดโดยอัตโนมัติ (ไม่ใช่จุดสุดท้าย)


## คู่มือ: เมนู ขอบเขต และการทดสอบแบบมีคลังความรู้ (0.8.2)

**เมนูซ้ายเรียงตามลำดับงาน** อ่านจากบนลงล่างครั้งเดียวจบ

| กลุ่ม | เมนู | ใช้ทำอะไร |
|---|---|---|
| (บนสุด) | ภาพรวม | สถานะทั้งระบบ |
| 1 เตรียมข้อมูล | คลังความรู้ / ชุดข้อมูลสอน | เอกสารให้โมเดลเปิดอ่าน / ตัวอย่างสอนโมเดล |
| 2 สร้างและทดสอบ | เทรนโมเดลใหม่ / ลองคุยกับโมเดล / ทดสอบและเปรียบเทียบ | |
| 3 นำไปใช้งาน | โมเดล (แท็บ: ใช้งานจริง, ในเครื่อง, นำเข้าจากที่อื่น) / ขอบเขตและการเชื่อมต่อ (แท็บ: ขอบเขตการตอบ, เชื่อมต่อระบบอื่น) | |
| ระบบ | เครื่องและตั้งค่า (แท็บ: เครื่องและพื้นที่, ตั้งค่า, คำศัพท์) | |

**คำที่เปลี่ยน**: ทะเบียนโมเดล = โมเดลที่ใช้งานจริง (สถานะ รอตรวจ → อนุมัติ → ใช้งานจริง → เก็บถาวร), ลงทะเบียน = เพิ่มโมเดลเข้ารายการ, Playground = ลองคุยกับโมเดล ไม่แน่ใจคำไหนเปิดแท็บ "คำศัพท์"

**ขอบเขตการตอบ** (เมนู ขอบเขตและการเชื่อมต่อ)
1. เคสอันตราย (red flag) เช่น พูดถึงการทำร้ายตัวเอง: ตอบข้อความตายตัวพร้อมเบอร์ช่วยเหลือ ไม่ผ่านโมเดล
2. หัวข้อต้องห้าม เช่น ขอวินิจฉัยโรค ขอขนาดยา: ตอบปฏิเสธตายตัว
3. คำทักทายสั้นๆ ข้ามการค้นคลัง
4. ถ้าเปิดคลังความรู้แต่ค้นไม่เจอ (คะแนนต่ำกว่า "ค่าความเกี่ยวข้องขั้นต่ำ") ตอบ "ไม่มีข้อมูล" ทันที กันโมเดลแต่งเอง
ช่อง "ลองพิมพ์คำถาม" ดูว่าถูกด่านไหนจับโดยไม่เรียกโมเดล; กด "คืนค่าเริ่มต้น" ถ้าแก้พัง

**ทดสอบแบบมีคลังความรู้**: ในหน้า "ทดสอบและเปรียบเทียบ" ติ๊ก "ทดสอบแบบมีคลังความรู้และขอบเขต" แล้วรันโมเดลเดิมเทียบกัน (เช่น faq-v3 กับ faq-v5) ใช้ชุดคำถามเดียวกัน ผลนี้ใกล้ความจริงที่ผู้ใช้เห็นที่สุด เพราะรวมด่านขอบเขตและเอกสารที่ดึงมา

**สอนแบบมีเอกสารอ้างอิง**: ตอนสร้างชุดข้อมูลจากข้อเท็จจริง เปิด "สอนแบบมีเอกสารอ้างอิง (RAG)" ถ้าตอนใช้งานจริงเปิดคลังความรู้ ตัวอย่างสอนจะแนบเอกสารเหมือนที่ระบบจะแนบ ทำให้โมเดลเรียน "อ่านเอกสารแล้วตอบ" และไม่ปฏิเสธทั้งที่เอกสารมีคำตอบ (เป็นสมมติฐานที่ต้องวัดด้วยโหมดทดสอบข้างบน ไม่ใช่ข้อสรุป)


## คู่มือ: เทรนโมเดลใหม่อย่างปลอดภัย (0.8.3)

**ควรเทรนใหม่เมื่อไหร่**: ข้อมูลเปลี่ยน (เบอร์ เวลา ราคา เรื่องใหม่) → แก้ที่ "คลังความรู้" ไม่ต้องเทรน; กฎ/ขอบเขตเปลี่ยน → แก้ที่ "ขอบเขตการตอบ" ไม่ต้องเทรน; นิสัยการตอบเปลี่ยน (น้ำเสียง รูปแบบ งานแบบใหม่) → เทรนรุ่นใหม่

**ขั้นตอนเทรนรุ่นใหม่**
1. เมนู โมเดล > ใช้งานจริง > รุ่นที่ใช้อยู่ > **การ์ดโมเดล** ดูค่าเดิมทั้งหมด แล้วกด **เทรนใหม่ด้วยค่าเดิม** (ชื่อรุ่นถัดไปตั้งให้ ไม่ทับของเดิม)
2. แก้ชุดข้อมูลหรือค่าที่ต้องการเปลี่ยนเพียงอย่างเดียวต่อครั้ง จะรู้ว่าอะไรทำให้ผลเปลี่ยน แล้วเริ่มเทรน
3. หลังเทรนเสร็จ กด "รันทดสอบ" ที่รุ่นใหม่ แล้วเทียบกับรุ่นที่ใช้อยู่ในหน้า "ทดสอบและเปรียบเทียบ" โดยติ๊ก **ทดสอบแบบมีคลังความรู้และขอบเขต** ใช้ชุดคำถามเดียวกัน
4. ในช่อง "บันทึก" ของรุ่นใหม่ เขียนว่าแก้อะไรจากรุ่นก่อน (การ์ดจะแสดงให้)
5. ผลดีกว่าและ red flag จับได้ 100% จึง อนุมัติ → เปิดใช้งานจริง ถ้ามีปัญหา กดย้อนกลับไปรุ่นเดิมได้ทันที เก็บรุ่นเก่าไว้จนรุ่นใหม่ผ่านการใช้งานจริงสักพัก

**ข้อสอบ "เอกสารขัดความจำ"**: ใช้เฉพาะโหมดมีคลังความรู้ ระบบแนบเอกสารที่เปลี่ยนเลขไปแล้ว ถ้าโมเดลยังตอบเลขเก่า แสดงว่ายังยึดความจำมากกว่าเอกสาร (ลองสอนแบบมีเอกสารอ้างอิง และอย่าฝังเลขที่เปลี่ยนบ่อยในคำตอบของชุดสอน) ข้อสอบกลุ่มนี้ไม่ถูกตรึง ต้องติ๊กเลือกเองในหน้าทดสอบ


## คู่มือ: ผลทดสอบ ส่งออก และวนปรับปรุงโมเดล (0.8.4)

**เปรียบเทียบเบื้องหลัง**: หน้า "ทดสอบและเปรียบเทียบ" เลือกโมเดลอย่างน้อย 2 ตัว กดเปรียบเทียบ ได้แถบความคืบหน้าทันที จะเปลี่ยนไปหน้าอื่นหรือปิดเบราว์เซอร์ก็ได้ งานรันต่อที่ backend กลับมาที่หน้านี้จะต่อจากเดิม และดูย้อนหลังได้ที่ "ประวัติการเปรียบเทียบล่าสุด" (ถ้าปิด backend กลางทางจะขึ้น "ถูกตัดกลางทาง" ต้องรันใหม่) รันได้ทีละงาน

**อ่านผล**: ตารางสรุปด้านบน → กล่อง "พลาดเพราะอะไร และควรทำอะไรต่อ" → ข้อที่มีโมเดลพลาด (เคสอันตรายขึ้นก่อน) ข้อที่ผ่านทั้งหมดพับไว้ กดดูได้

**ส่งผลมาให้คนอื่น/ผู้ช่วยดู**: ปุ่ม "คัดลอกเฉพาะข้อที่พลาด" แล้วแปะ (สั้นที่สุด) หรือ "CSV (Excel)" / "JSON" เก็บเป็นไฟล์ ส่วนรอบทดสอบเดี่ยวมีปุ่ม CSV/JSON ในหัวผลทดสอบ

**วงรอบปรับปรุงโมเดล**
1. รันเปรียบเทียบแบบมีคลังความรู้ → ดู "พลาดเพราะอะไร"
2. กด "ร่างข้อมูลสอนจากข้อที่พลาด" ที่โมเดลที่สนใจ → ระบบเปิดตารางข้อเท็จจริงในหน้าชุดข้อมูลพร้อมร่าง
3. เติม "คำตอบ" ที่ว่าง ตรวจคำถาม/คำสำคัญ ถ้าเรื่องเดิมเขียนคำถามสำนวนอื่นเพิ่ม (แถวที่ไม่มีคำตอบจะไม่ถูกสร้าง) แล้วสร้างชุดข้อมูลใหม่
4. เขียน **ข้อสอบใหม่** แทนข้อที่เอาไปสอนแล้ว (ข้อสอบเดิมไม่ยุติธรรมอีก)
5. เทรนรุ่นใหม่ (การ์ดโมเดล > เทรนใหม่ด้วยค่าเดิม) → เปรียบเทียบกับรุ่นเดิม → เปิดการ์ดโมเดลดูป้ายเตือนก่อนอนุมัติ

**ป้ายในการ์ดโมเดล**: เขียว = ปกติ, เหลือง = ควรระวัง, แดง = ห้ามอนุมัติ (เช่น พลาดเคสอันตราย) ป้ายเหลืองที่พบบ่อย: "ผลทดสอบไม่มีคลังความรู้", "ชุดโจทย์เปลี่ยนไปจากตอนทดสอบ", "ช่องว่าง train/val กว้าง" (เสี่ยงท่องจำ แก้ด้วยข้อมูลที่หลากหลายขึ้นหรือลดรอบ)

## คู่มือ: กันถามซ้ำ ตรวจเลข และคำตอบสำเร็จรูป (0.8.5)

**กันถามซ้ำ/สแปม** (เมนู ขอบเขตและการเชื่อมต่อ > ป้องกันถามซ้ำ/สแปม) ใช้กับ API ที่ระบบอื่นเรียก
1. เลือกชุดค่า **ผ่อนปรน / ปกติ / เข้มงวด** แล้วปรับเกณฑ์เองได้ ตัวอย่างค่า "ปกติ": ถามข้อเดิมครั้งที่ 3 ใช้คำตอบเดิม (ไม่เรียกโมเดล) ครั้งที่ 5 เตือน ครั้งที่ 8 พัก 1 นาที (ทำผิดอีกพัก 5 นาที แล้ว 30 นาที)
2. ก่อนบันทึก กด **จำลอง**: ใส่คำถาม จำนวนครั้ง และช่วงห่าง ดูตารางว่าแต่ละครั้งได้ผลอะไร และประหยัดการเรียกโมเดลกี่ครั้ง (ไม่เรียกโมเดลจริง ไม่กระทบสถานะจริง)
3. กดบันทึก มีผลทันที ไม่ต้องรีสตาร์ท
4. ดู "สถานะสด" ว่าตอนนี้ใครถูกพัก กด **ปลดล็อก** ได้ถ้าพักผิดคน
- เคสอันตราย (เช่น อยากทำร้ายตัวเอง) และกฎตอบตายตัว **ไม่ถูกจำกัดเลย** ถามกี่ครั้งก็ได้เบอร์ฉุกเฉินเสมอ
- ระบบเว็บ/LINE ที่เรียก API ควรส่ง `client_id` (รหัสผู้ใช้แต่ละคน) มาด้วย จะได้พักเฉพาะคนที่สแปม ไม่ใช่ทุกคนที่ใช้คีย์เดียวกัน; ถูกพักจะได้ HTTP 429 พร้อมหัว `Retry-After` และ `detail.retry_after` (วินาที) ให้ระบบเรียกแสดงข้อความรอ
- ระบบไม่เก็บข้อความคำถามในสถานะ/เหตุการณ์ (เก็บแค่ความยาวกับรหัสย่อ) ข้อมูลอยู่ในหน่วยความจำ รีสตาร์ท backend แล้วเริ่มนับใหม่
- หน้า "ลองคุยกับโมเดล" ไม่ถูกจำกัดโดยค่าเริ่มต้น (ติ๊กปิดได้ในหน้าตั้งค่าเมื่ออยากลองอาการจริง)

**ตรวจเลขในคำตอบ** (หน้าขอบเขตการตอบ > ตรวจเลขในคำตอบ): โมเดลเล็กชอบแต่งเบอร์โทรหรือเวลา ระบบจึงตรวจว่าเลขในคำตอบมีในเอกสารที่ค้นมาไหม ไม่มี → แทนที่ด้วยข้อความปลอดภัย ("ตัวเลขยังยืนยันกับเอกสารไม่ได้ สอบถามเจ้าหน้าที่") เพิ่มเลขที่โมเดลพูดได้เสมอ (เช่น 1669) ในช่อง "เลขที่อนุญาตเสมอ" ถ้ากรณีใดเลขถูกแต่ถูกแทนที่ผิด (เช่น เขียนเลขต่างรูป 074 999 123 vs 074-999-123 ตรวจให้แล้วระดับตัวเลขล้วน) ให้เพิ่มลงรายการอนุญาตหรือแก้เอกสารให้เขียนรูปแบบเดียวกัน ดูคำตอบเดิมของโมเดลได้ในผลทดสอบ

**คำตอบสำเร็จรูป**: คำถามที่คำตอบไม่เปลี่ยน (แนะนำตัว ทำอะไรได้บ้าง) ตั้งเป็นกฎให้ตอบข้อความตายตัว ไม่เสี่ยงโมเดลตอบเลอะ ลองพิมพ์ในช่อง "ลองข้อความ" ก่อนบันทึก

**ปรับการค้นเอกสาร**: ในผลทดสอบมี "คะแนนสูงสุด" ของทุกข้อ ถ้าข้อที่ควรตอบ "ไม่มีข้อมูล" ยังมีคะแนนสูงใกล้กับข้อที่ตอบได้ ให้ขยับ **เกณฑ์ความเกี่ยวข้อง** ในหน้าขอบเขตขึ้น (ลอง 0.35) และลดจำนวนชิ้นเอกสารเหลือ 3 แล้วรันเปรียบเทียบใหม่ ถ้าสูงเกินจะเริ่มตอบ "ไม่มีข้อมูล" ทั้งที่มี ให้ลดกลับ

## คู่มือ: ข้อสอบแหย่โมเดล รายงานความมั่นใจ และเดโม (0.8.6)

**หาช่องโหว่ด้วยข้อสอบแหย่โมเดล**
1. โหลดแพ็ก 02 พร้อมคลังความรู้ก่อน (`python load_sample_pack.py --reset --pack 2 --kb`) แล้วเพิ่มแพ็ก 03 (`python load_sample_pack.py --pack 3`) จะได้ข้อใหม่ 61 ข้อ หมวดขึ้นต้น "แหย่:" (ไม่ปักหมุด ถ้าจะรันเฉพาะกลุ่มนี้ให้ติ๊กเลือกในหน้าทดสอบ)
2. รันเปรียบเทียบแบบมีคลังความรู้ ที่ผลกดปุ่ม **รายงานความมั่นใจ (.md)** ได้ไฟล์สรุปสำหรับให้หัวหน้าอ่าน
3. ข้อที่พลาดในกลุ่มแหย่: อ่านคำตอบจริงก่อน (ข้อสอบตรวจด้วยคำสำคัญ บางข้อตอบถูกแต่ใช้คำอื่น) ถ้าพลาดจริงแก้ที่ตัวกฎ: เคสอันตรายที่พูดอ้อมไม่ตรงกฎ → เพิ่มคำในกฎ "เคสอันตราย" หน้าขอบเขตการตอบ; ตอบเรื่องที่ไม่ควรตอบ → เพิ่มหัวข้อต้องห้าม; แต่งข้อมูลที่ไม่มี → ปรับเกณฑ์ความเกี่ยวข้อง; ข้อสอบที่เอาไปสอนแล้วให้เขียนข้อใหม่แทน

**เว็บแชทจำลอง + LINE (โฟลเดอร์ `demo/`)** ใช้ Node 18 ขึ้นไป ไม่ต้อง `npm install`
1. สร้างคีย์ API ในหน้า "เชื่อมต่อระบบอื่น (API)" แล้วคัดลอก `demo/.env.example` เป็น `demo/.env` ใส่ `LLM_API_KEY` (ถ้า LLM Studio อยู่เครื่องอื่นแก้ `LLM_API_URL`)
2. รัน `cd demo` แล้ว `node server.mjs` เปิด http://localhost:3000 ต้องมีโมเดลที่ตั้งเป็น "ใช้งานจริง" และ backend รันอยู่
3. ผูก LINE: สร้าง Messaging API channel ใน LINE Developers ใส่ `LINE_CHANNEL_SECRET` และ `LINE_CHANNEL_ACCESS_TOKEN` ใน `.env` แล้วตั้ง Webhook URL เป็น `https://<ที่อยู่สาธารณะ>/line/webhook` (LINE ต้องเรียกเข้ามาทางอินเทอร์เน็ต เดโมใช้ช่องทางชั่วคราว เช่น tunnel ได้ **เฉพาะข้อมูลสมมติ** ส่วนของจริงต้องออกแบบเครือข่ายกับฝ่ายเครือข่าย/หัวหน้าก่อน)
4. เทสต์ตัวกลาง: `node --test demo/test.mjs`
- ตัวกลางส่ง `client_id` (แฮชจากรหัสผู้ใช้) ไปทุกคำถาม ระบบกันถามซ้ำจึงพักเฉพาะคนที่สแปม
- ข้อจำกัด: ตอบเฉพาะข้อความตัวอักษร (รูป/สติกเกอร์ถูกข้าม) และ reply token ของ LINE หมดอายุเร็ว ถ้าโมเดลช้ามากอาจตอบกลับไม่ทัน ควรทดสอบเวลาตอบจริงก่อนเดโม
